# MyShop – Setup and Deployment Summary

Summary of steps used to configure the app for local development and Azure deployment.

---

## 1. Configuration (appsettings)

- **appsettings.json**  
  Base config. `ConnectionStrings:DefaultConnection` is left empty. Other shared settings (e.g. `AllowedHosts`, `PayPalSettings`) live here.

- **appsettings.Development.json**  
  Used when `ASPNETCORE_ENVIRONMENT=Development`. Contains the **local SQL Server** connection string (e.g. `Data Source=...\LOCALSQLSERVER;Initial Catalog=MyShop_LocalDB;...`).

- **appsettings.Production.json**  
  Used when `ASPNETCORE_ENVIRONMENT=Production`. Contains **Production** logging and the **Azure SQL** connection string (`Server=tcp:...database.windows.net,1433;Initial Catalog=...;User ID=...;Password=...;Encrypt=True;...`).

Environment is chosen at runtime (launch profile locally, App Service setting in Azure), so the correct connection string is picked automatically.

---

## 2. Running locally

- From the **MyShop** project folder (where `MyShop.csproj` is):
  - `dotnet run` or `dotnet watch run`
- The app uses the Development environment (from launch profile) and reads `appsettings.Development.json`, so it connects to your local DB.
- No need to set `ASPNETCORE_ENVIRONMENT` in the shell for normal local dev.

---

## 3. Deploying to Azure

- **Source:** Azure App Service → **Deployment Center** → Source: **GitHub** → repo `VariusValinium22/myshop`, branch **master**.
- **Build:** GitHub Actions (generated by Azure).
- **Stack:** In App Service **Configuration** / **General settings**, set the stack to **.NET 6** so the runtime matches the project (`net6.0`).

---

## 4. Azure App settings (environment variables)

In the Azure portal: **App Service** → **Settings** → **Environment variables** → **App settings** (not the “Configuration” tab labels; use “App settings” in the Environment variables area).

Add/confirm:

| Name | Value |
|------|--------|
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `ConnectionStrings__DefaultConnection` | Your full Azure SQL connection string |
| `ASPNETCORE_DETAILEDERRORS` | `true` (optional, for easier debugging) |

**Important:** The connection string key must be **`ConnectionStrings__DefaultConnection`** (double underscore `__`). A single underscore will not bind to `Configuration["ConnectionStrings:DefaultConnection"]`.  
These settings override values from `appsettings.Production.json`, so you can change the production DB (e.g. to a different server) without redeploying.

---

## 5. Fixing the startup error (FileNotFoundException for 7.0 assemblies)

The app targets **.NET 6** but had **Entity Framework Core 7.x** packages. That pulled in 7.0 assemblies (e.g. `Microsoft.Extensions.DependencyInjection.Abstractions, Version=7.0.0.0`) that the Azure .NET 6 runtime doesn’t provide, causing a crash on startup.

**Changes made:**

- In **MyShop.csproj**, downgrade EF Core to 6.x:
  - `Microsoft.EntityFrameworkCore.SqlServer` → **6.0.25**
  - `Microsoft.EntityFrameworkCore.Tools` → **6.0.25**
- In **Program.cs**, remove the unused `using Microsoft.EntityFrameworkCore;` (the `AddDbContext` block was already commented out).

After that, restore, build, push to Git, and let Azure redeploy (or redeploy manually).

---

## 6. Build tip (file in use)

If `dotnet build` fails with “The process cannot access the file ... because it is being used by another process” and the lock is held by **MyShop**, a previous instance is still running (e.g. `dotnet watch run` in another terminal). Stop that process (Ctrl+C in the run terminal), then run `dotnet build` again.

## 7. Deploying to HomeLab

You can run MyShop on your own server (Windows or Linux) and point it at a different database (e.g. SQL Server on the HomeLab) using environment variables. No code changes are required.

### 7.1 Publish the app

On your dev machine, from the **MyShop** project folder:

```bash
dotnet publish -c Release -o ./publish
```

The output will be in `./publish`. Zip it or copy the contents to the HomeLab server (e.g. `C:\inetpub\MyShop` on Windows or `/var/www/myshop` on Linux).

**Optional – self-contained (no .NET installed on server):**

```bash
# Windows server
dotnet publish -c Release -r win-x64 --self-contained true -o ./publish

# Linux server (e.g. x64)
dotnet publish -c Release -r linux-x64 --self-contained true -o ./publish
```

### 7.2 Set environment variables on the HomeLab server

On the server, set these so the app uses **Production** and your **HomeLab database** (they override `appsettings.Production.json`):

| Name | Value |
|------|--------|
| `ASPNETCORE_ENVIRONMENT` | `Production` |
| `ConnectionStrings__DefaultConnection` | Your HomeLab SQL Server connection string (double underscore `__`) |

Example (HomeLab SQL Server on the same machine):  
`Server=.;Initial Catalog=MyShop_HomeLab;User ID=...;Password=...;Encrypt=False`  
(or use a named instance / server hostname as needed).

---

### Option A: Windows Server with IIS

1. **Install on the server**
   - [.NET 6.0 Hosting Bundle](https://dotnet.microsoft.com/download/dotnet/6.0) (includes runtime + IIS module).
   - After install, run `iisreset` (or restart IIS from Services).

2. **Copy the publish folder**  
   e.g. to `C:\inetpub\MyShop`.

3. **Create the site in IIS**
   - Open **IIS Manager** → **Sites** → **Add Website**.
   - **Site name:** e.g. `MyShop`.
   - **Physical path:** `C:\inetpub\MyShop`.
   - **Binding:** e.g. `http` port 80 and/or `https` with a certificate; set **Host name** if you use a DNS name (e.g. `myshop.homelab.local`).
   - **Application pool:** Create or select one → **.NET CLR version:** *No Managed Code*; **Identity:** ApplicationPoolIdentity or a custom account if the app needs extra permissions.

4. **Environment variables for the app**
   - Select the **Application pool** used by MyShop → **Advanced Settings** → **Process Model** → **Load User Profile** = True (optional).
   - Easiest: set variables in **web.config** (IIS will set them for the process). In the publish folder, ensure there is a **web.config**. If not, add one next to the main DLL with something like:
   ```xml
   <?xml version="1.0" encoding="utf-8"?>
   <configuration>
     <location path="." inheritInChildApplications="false">
       <system.webServer>
         <handlers>
           <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" />
         </handlers>
         <aspNetCore processPath="dotnet"
                     arguments=".\MyShop.dll"
                     stdoutLogEnabled="true"
                     stdoutLogFile=".\logs\stdout"
                     hostingModel="inprocess">
           <environmentVariables>
             <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
             <environmentVariable name="ConnectionStrings__DefaultConnection" value="YOUR_HOMELAB_SQL_CONNECTION_STRING" />
           </environmentVariables>
         </aspNetCore>
       </system.webServer>
     </location>
   </configuration>
   ```
   Replace `YOUR_HOMELAB_SQL_CONNECTION_STRING` with your actual connection string.  
   Or use **IIS Application Pool** → **Configuration Editor** → `system.applicationHost/applicationPools` → your pool → **Environment Variables** to set `ASPNETCORE_ENVIRONMENT` and `ConnectionStrings__DefaultConnection` (less common; web.config is usually simpler).

5. **Restart the site** and browse to the URL you configured.

---

### Option B: Linux server (Kestrel)

1. **Install .NET 6 runtime** on the server (or use a self-contained publish from 7.1).

   Ubuntu/Debian example:
   ```bash
   wget https://packages.microsoft.com/config/ubuntu/22.04/packages-microsoft-prod.deb -O packages-microsoft-prod.deb
   sudo dpkg -i packages-microsoft-prod.deb
   sudo apt-get update && sudo apt-get install -y aspnetcore-runtime-6.0
   ```

2. **Copy the publish output** to the server, e.g. `/var/www/myshop`.

3. **Set environment variables**  
   Create a small env file or export before running, e.g.:
   ```bash
   export ASPNETCORE_ENVIRONMENT=Production
   export ConnectionStrings__DefaultConnection="Server=...;Initial Catalog=MyShop_HomeLab;User ID=...;Password=...;Encrypt=False"
   ```

4. **Run the app**
   ```bash
   cd /var/www/myshop
   dotnet MyShop.dll
   ```
   Or run as a **systemd service** so it starts on boot and restarts on failure. Example `/etc/systemd/system/myshop.service`:
   ```ini
   [Unit]
   Description=MyShop ASP.NET Core app
   After=network.target

   [Service]
   WorkingDirectory=/var/www/myshop
   ExecStart=/usr/bin/dotnet /var/www/myshop/MyShop.dll
   Restart=always
   RestartSec=10
   Environment=ASPNETCORE_ENVIRONMENT=Production
   Environment=ASPNETCORE_URLS=http://localhost:5000
   Environment=ConnectionStrings__DefaultConnection=Server=...;Initial Catalog=MyShop_HomeLab;User ID=...;Password=...;Encrypt=False

   [Install]
   WantedBy=multi-user.target
   ```
   Then:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable myshop
   sudo systemctl start myshop
   sudo systemctl status myshop
   ```
   Put a reverse proxy (e.g. **nginx** or **Caddy**) in front of `http://localhost:5000` for HTTPS and host name.

---

### Summary for HomeLab

- **Publish** once with `dotnet publish -c Release -o ./publish`.
- **Copy** the publish folder to the server.
- **Set** `ASPNETCORE_ENVIRONMENT=Production` and `ConnectionStrings__DefaultConnection` to your HomeLab SQL connection string (double underscore) on the server (web.config on IIS, or env vars / systemd on Linux).
- **Run** under IIS (Windows) or Kestrel + reverse proxy (Linux).  
Azure continues to use its own App settings (Azure SQL); HomeLab uses the connection string you set on the HomeLab server.

---

## Quick checklist

- [ ] `appsettings.json` has empty or minimal `DefaultConnection`; environment-specific files have the real connection strings.
- [ ] `appsettings.Production.json` has the Azure SQL connection string and production logging.
- [ ] Azure App Service stack is **.NET 6**.
- [ ] App settings include `ASPNETCORE_ENVIRONMENT=Production` and `ConnectionStrings__DefaultConnection` (double underscore) with the Azure SQL connection string.
- [ ] EF Core packages are **6.x** (not 7.x) when targeting `net6.0`.
- [ ] **HomeLab:** Publish → copy to server → set `ASPNETCORE_ENVIRONMENT` and `ConnectionStrings__DefaultConnection` on the server; run under IIS (Windows) or Kestrel + reverse proxy (Linux).
- [ ] Stop any running MyShop process before building if you see “file in use” errors.
